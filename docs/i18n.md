# CareerPulse Internationalization (i18n)

CareerPulse ships a Simplified Chinese (`zh-CN`) and English (`en`) interface.

* **Default language is `zh-CN`** — the app never auto-detects the browser language.
* **Web** stores the choice in `localStorage` under `careerpulse_lang`
  (`app/static/js/i18n.js`).
* **Chrome extension** stores its own choice in `chrome.storage.local` under
  `language` (`extension/i18n.js`). Web and extension settings are independent.
* Switching language re-renders the current page. If the page holds unsaved form
  edits, the user is asked to confirm first.
* 金额一律以人民币（元）计价，按月薪口径展示，**不做任何币种换算**。
  Money is always CNY (yuan) and is presented as a monthly salary. Amounts are
  never converted to another currency.

## Module layout

| Path | Purpose |
| --- | --- |
| `app/static/js/i18n.js` | Web core: `t()`, language read/write/switch, fallback, dev warnings, date/number formatting |
| `app/static/js/locales/*.js` | Web catalogs, one file per domain, **both languages in the same file** |
| `extension/i18n.js` | Extension core (same API, `chrome.storage.local` persistence) |
| `extension/locales/common.js` | **Generated** mirror of the web cross-cutting namespaces |
| `extension/locales/extension.js` | Extension catalogs (`popup`, `overlay`, `upload`, `queue`, `background`) |
| `extension/error-messages.js` | Extension error-code → message mapping (mirrors `api.js`) |
| `extension/scripts/sync-common-locale.mjs` | Regenerates the extension common catalog from the web one |

Load order (browser): `i18n.js` first, then every `locales/*.js`, then the app
scripts. Never call `t()` at module top level — resolve copy inside render
functions so a language switch can re-render.

Extension load order: `i18n.js`, `locales/common.js`, `locales/extension.js`,
`error-messages.js`, then `popup.js` (see `popup.html`) or `normalize.js`,
`ats-adapters.js`, `content.js` (see `manifest.json` → `content_scripts`).

Shared terminology is generated, never hand-copied:

```bash
node extension/scripts/sync-common-locale.mjs          # write
node extension/scripts/sync-common-locale.mjs --check  # CI / test mode
```

`extension/tests/i18n-parity.test.js` fails when the generated file drifts or
when a shared key is edited on only one side.

## Key naming

* Dotted, lowercase, last segment camelCase where needed:
  `nav.jobs`, `actions.save`, `status.loading`, `errors.jobNotFound`,
  `settings.profile.title`, `shell.scrape.columns.source`.
* `data-i18n*` attributes in `index.html` bind static markup to keys.
* Interpolation uses `{name}` placeholders (`{count}`, `{name}`, `{total}`,
  `{error}`, `{status}` …).
* Plurals: the English value may be `"1 job|{count} jobs"`. The first form is
  used when `params.count === 1`. Chinese values never contain `|`.
* Cross-cutting keys live in `locales/common.js` (`nav`, `actions`, `status`,
  `errors`, `fields`, `a11y`, `time`, `common`, `toast`, `modal`, `i18n`,
  `notifications`). Page copy lives in that page's catalog.
* The site footer is shell markup in `index.html`; its copy lives in
  `locales/shell.js` under its own `footer.*` namespace (not `shell.footer.*`),
  so the footer columns keep reusing the shared `nav.*` labels. Its runtime
  helpers are in `js/footer.js`, which is part of the static-copy audit.
* The extension mirrors `nav`, `actions`, `status`, `errors`, `fields`, `a11y`,
  `time` and `common` in `extension/locales/common.js`; those values must be
  **identical** on both sides, which `extension/tests/i18n-parity.test.js`
  enforces.

## What is translated and what is not

**Translated (interface copy):** navigation, buttons, form labels and
placeholders, page titles, empty/loading states, toasts, modals and confirms,
success/error messages, `title`/`aria-label`/`alt` accessibility text, dates,
relative times, calendar UI, onboarding wizard, extension popup, autofill
overlay, queue prompts, download prompts, operation status.

**Never translated (raw business content):** job descriptions and titles scraped
from job boards, company names, user-entered text, AI-generated resumes, cover
letters and analyses, email bodies and templates, third-party job board pages,
developer docs, the BOSS Zhipin adapter itself.

Dynamic content must be marked in code so reviewers can tell it apart from
interface copy: a comment `/* raw business content */` (or `// raw business
content`) next to the interpolation. Interface strings must never appear as raw
literals — they must come from `t()`.

## Missing keys

`t()` resolution order: current language → English → the key itself. Missing
keys are recorded (`i18n.getMissingKeys()`, `i18n.getFallbackKeys()`) and warn
through `console.warn` in development (localhost, `?i18n_debug=1`, or
`window.__CP_I18N_DEBUG__ = true`). Tests assert both the warning and the
fallback behavior.

## Language switching behaviour

* Web: the `中文 / EN` control sits next to the theme button in the navbar.
  It writes `localStorage['careerpulse_lang']`, re-applies static markup, and
  re-renders the active view (`rerenderForLanguage()` in `app.js`).
* Extension: the popup has its own `中文 / EN` control, and the autofill overlay
  has a compact toggle in its header. Both write `chrome.storage.local.language`
  and follow each other through `chrome.storage.onChanged`.
* The two settings never interfere: different storage areas, different keys.
* Before discarding unsaved edits, the web app asks for confirmation
  (`confirmDiscardUnsavedChanges()`): explicit `registerDirtyCheck()` callbacks
  plus a baseline snapshot of the form controls in `#app`. Views that fill
  fields programmatically call `refreshFormBaseline()` afterwards, and live
  filters are marked `data-dirty-ignore`.

### One key and one predicate per feature (job-board panel ⇄ popup)

The panel that floats on the job board and the extension popup are two entry
points into the same feature, so they must share both the copy and the decision:

* **One sentence, one key.** 「本页没有可填写的申请表」 / "No application form on
  this page" lives in `overlay.panelNoForm`; the popup's grey-out hint calls
  `t('overlay.panelNoForm')` instead of adding a `popup.*` duplicate, so editing
  the sentence updates both surfaces and `i18n-parity.test.js` tracks one copy.
* **One predicate.** Whether the fill button is usable comes from
  `pageHasApplicationForm()` in `content.js`: the panel calls it directly, the
  popup asks over the `detectForm` message. Two independent checks are how
  面板置灰、弹窗却亮蓝 happens.
* **Asynchronously discovered state must be re-rendered** when the page or the
  language changes. The panel repaints through the idempotent `paintPanel()` and
  re-judges form availability on every page scan; the popup re-renders its
  grey-out reason and `title` from `renderStaticCopy()`. A language switch must
  never leave stale copy (or a stale disabled button) behind.
* When the answer is unknown — the content script is absent, or an older one
  does not know `detectForm` — the UI stays usable rather than blocking the
  user; the click path then explains itself (`popup.refreshRequired`).

## Backend error contract

User-visible backend errors no longer depend on English strings:

```json
{ "code": "resume.not_found", "params": {}, "detail": "Resume not found" }
```

* `code` — stable identifier, the only thing frontends translate.
* `params` — values interpolated into the localized message.
* `detail` — non-localized English text kept for logs, curl and older clients.

Frontend mapping is automatic: `resume.not_found` → `errors.resumeNotFound`
(`errorKeyFromCode` in `app/static/js/api.js`). Unknown codes fall back to
`errors.dynamic` with the raw detail, so third-party/AI/provider messages keep
their original text behind a localized prefix.

Backend usage:

```python
from app.errors import AppError

raise AppError("resume.not_found", status_code=404)
raise AppError("scrape.source_failed", status_code=502, params={"source": name},
               detail=f"Source {name} failed")
```

## Dates, times and numbers

All formatting goes through `i18n.formatDate`, `formatDateLong`,
`formatDateTime`, `formatTime`, `formatMonthYear`, `formatWeekday`,
`weekdayNames`, `formatRelativeTime`, `formatNumber`, `formatPercent`. Never
hardcode `'en-US'` in a `toLocaleDateString` call. `formatCurrency` stays CNY —
金额一律人民币口径，永不换算。

## Leak tooling

`node scripts/find-english-leaks.mjs` loads the real catalogs and reports two
classes of problems:

1. key drift — a key defined in one language but not the other;
2. English leaks — a `zh-CN` value byte-identical to the English one that
   contains no Chinese characters. Brand names, acronyms and placeholders are
   listed in `INTENTIONALLY_IDENTICAL` in the script; add to that list only when
   the Chinese UI genuinely shows the same text.

A missing key renders as the raw key name in the UI, which is why the
key-existence assertion in `i18n.test.js` matters as much as the copy audit.

## Maintenance rules (enforced in code review)

1. New or changed user-visible copy **must not** be hardcoded in templates or view
   scripts.
2. Add or update a translation key; provide **both** `zh-CN` and `en`.
3. Add the necessary tests (i18n unit test or the static audit test).
4. Mark dynamic content explicitly as interface copy vs. raw business content.
5. Run `app/static/tests/i18n-audit.test.js` and
   `extension/tests/i18n-audit.test.js` — they fail when new hardcoded English
   copy appears in a migrated file.

## Tests

```bash
cd app/static && ./node_modules/.bin/vitest run     # includes i18n + audit tests
cd extension && ./node_modules/.bin/vitest run      # includes parity + audit tests
uv run pytest                                       # backend error-code contract
```

| Suite | What it enforces |
| --- | --- |
| `app/static/tests/i18n.test.js` | zh-CN default, persistence, interpolation, fallback + dev warning, key parity between languages, **every `t()`/`data-i18n*` key used by the frontend exists**, date/number localization, static markup binding, unsaved-change detection |
| `app/static/tests/i18n-audit.test.js` | no hardcoded interface copy in migrated files, **including prose that sits directly inside multi-line template literals**, no hardcoded `en-US` date locales, no currency conversion |
| `extension/tests/i18n.test.js` | extension default, `chrome.storage.local` persistence, cross-context language changes, overlay/popup/queue copy, error-code mapping |
| `extension/tests/i18n-parity.test.js` | web ⇄ extension keys and wording stay identical; generated catalog up to date; every backend error code translated on both sides |
| `extension/tests/i18n-audit.test.js` | no hardcoded copy in popup/content/background, i18n loaded by every entry point |
| `tests/test_i18n_error_codes.py` | `{code, params, detail}` contract, no `HTTPException` string details left in routers, every raised code exists in the catalog |

Frontend tests run with the interface language forced to English
(`tests/setup.js`), so existing DOM assertions keep working; i18n tests call
`resetI18n()` to reload the module and verify the Chinese default.
